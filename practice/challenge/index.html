Contest rule: when stuck, restate constraints → estimate complexity → name 2 candidate patterns → switch problem. Upsolve misses in Mixed-Pattern Practice and the Pattern Recognition sheet.

Upsolve lab - three worked classifications

Contest skill is upsolving: take a problem you missed and run it through Understand, Think, Hint, Key observation, Approach. Open each step only when stuck.

Lab 1 - Pair with a target sum Easy Two Sum (LeetCode #1)

Understand. Unsorted array, return indices of two entries adding to a target. One pass wanted.

Think. For each value, the partner it needs is fully determined. What structure remembers what you already saw?

Hint 1 - what to inspect

The complement of each element, and whether it appeared before.

Hint 2 - what property matters

Order of arrival matters (indices), values are arbitrary: no sortedness to exploit.

Hint 3 - what pattern becomes possible

Complement lookup in a hash map: check before inserting.

Key observation. need = target minus x is known at the moment x is seen, so one lookup decides the fate of x.

Approach. Complement Lookup preset: for x, if the map has target-x return both indices, else store x. O(n) average, O(n) space.

Lab 2 - Minimum feasible speed Hard Koko Eating Bananas (LeetCode #875)

Understand. Piles of bananas, hourly speed X, deadline H hours. Smallest X that finishes everything.

Think. Trying every X is too slow. What happens to feasibility as X grows?

Hint 1 - what to inspect

Whether "X works" can ever flip back to failing for a larger X.

Hint 2 - what property matters

Monotonicity: if speed X finishes in time, any faster speed does too.

Hint 3 - what pattern becomes possible

Binary search over the answer space, not over array data.

Key observation. Feasibility is monotone in X, and checking one X costs O(n): exactly the search-on-answer shape.

Approach. Binary Search on Answer preset: lo=1, hi=max pile, keep the smallest feasible. O(n log M).

Lab 3 - Longest increasing subsequence Medium Longest Increasing Subsequence (LeetCode #300)

Understand. Length (not the sequence itself) of the longest strictly increasing subsequence.

Think. O(n squared) DP compares every pair. What information about best tails so far is actually needed?

Hint 1 - what to inspect

For each possible subsequence length, only the smallest achievable tail matters.

Hint 2 - what property matters

Those tails stay sorted, so each new value has a binary-searchable home.

Hint 3 - what pattern becomes possible

Tails array plus lower bound: replace, never append blindly.

Key observation. tails[k] = minimum tail of an increasing subsequence of length k+1 stays sorted, so each x lower-bounds its pile in O(log n).

Approach. LIS preset: iterate, lower-bound x in tails, replace or append. Answer = tails length. O(n log n).
