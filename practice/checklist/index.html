Problem-Solving Checklist

The original checklist, unchanged.

Key notes

Run through these steps for every new problem:

Before Coding

  • What exactly is being asked?
  • What are the constraints? (n range, time limit, memory limit)
  • What is the brute-force approach?
  • What is its complexity? Is it too slow?
  • Can hashing help? (frequency counting, two-sum pattern)
  • Can sorting help? (two pointers, sliding window)
  • Can two pointers help? (sorted array, window)
  • Can binary search help? (ordered answer space)
  • Is this a graph/tree problem? (connections, paths, dependencies)
  • Is this DP? (overlapping subproblems, optimal substructure)
  • Can the answer space be searched? (binary search on answer)
  • What edge cases exist? (empty, single element, duplicates, negative)
  • Can I prove the approach works? (correctness argument)
  • What is the final complexity? (time + space)

After Coding

  • Test with the given examples
  • Test with edge cases (empty input, single element)
  • Test with maximum constraints
  • Check for integer overflow
  • Verify space complexity
  • Can the code be simplified?
