Topic 5 · Two Pointers & Sliding Window

LevelC
PrerequisitesArrays, sorting, Big-O
Estimated time60–90 min
ProgressionWarm-up → Easy → Medium → Hard
Learn → Understand → Dry run → Warm-up → Easy → Medium → Hard → Review

Intuition

Two indices moving monotonically replace nested loops: opposite ends on sorted data, fast/slow for in-place edits, windows for contiguous ranges.

Learn: Opposite pointers, fast/slow pointers, fixed window, variable window  ·  Practice: Warm-ups -> Easy -> Medium -> Hard

How to recognize this pattern

Reach for it when:
  • Sorted array + a pair/triplet condition (sum, closest, container).
  • In-place rewrite or dedup (fast/slow) on an array.
  • Contiguous subarray/substring with a monotonic window property.
  • Partitioning around a pivot.
Red flags — probably NOT this:
  • Data is unsorted and order carries no meaning.
  • You must enumerate ALL subarrays, not just find an optimum.
  • The window property is not monotonic (e.g. shrinking a valid window can make it valid again for the wrong reason — negatives in sum windows).
  • You need random access history — consider prefix sums / hashing instead.

Worked example — Two Sum II — sorted pair

Problem. Sorted a=[2,7,11,15], target 9. Return 1-based indices.

  1. What should we notice? Sorted + pair sum: the ends carry maximum information.
  2. Naive thought. Check all pairs: O(n²) comparisons.
  3. Key observation. If a[L]+a[R] is too small, a[L] pairs with nothing (even the biggest partner fails) — L is dead. Too big mirrors to R.
  4. Optimized strategy. Start L=0,R=3 (2+15=17>9 → R--); L=0,R=2 (13>9 → R--); L=0,R=1 (9=9 ✓).
  5. Step-by-step. Sliding-window twin: max sum of k=3 in [1,4,2,10,2,3,1] — add right, drop left: 7,16,14,15,6.
  6. Final answer. Indices (1,2). Window best 16.
  7. Complexity. O(n) time, O(1) space — each pointer moves monotonically.
  8. What to remember. Sorted + pair → opposite ends. Contiguous + fixed/constrained → window that only slides forward.

Quick reference

Topic 5 · Two Pointers & Sliding Window

When would you actually use this? Use two pointers on sorted arrays or sliding window for contiguous subarray/substring problems. They eliminate nested loops -- turning O(n^2) into O(n).

Algorithm — Two Pointers Templates

// Pattern 1: Opposite Ends (sorted array)
int left = 0, right = arr.length - 1;
while (left < right) {
    int sum = arr[left] + arr[right];
    if (sum == target) { /* found */ left++; right--; }
    else if (sum < target) left++;
    else right--;
}

// Pattern 2: Same Direction (Fast & Slow — remove duplicates, partition)
int slow = 0;
for (int fast = 0; fast < arr.length; fast++) {
    if (arr[fast] != arr[slow]) {
        slow++;
        arr[slow] = arr[fast];
    }
}

// Pattern 3: Merge Two Sorted Arrays
int i = 0, j = 0;
while (i < a.length && j < b.length) {
    if (a[i] <= b[j]) result.add(a[i++]);
    else result.add(b[j++]);
}

Algorithm — Sliding Window Templates

// Fixed Size Window
int windowSum = 0;
for (int i = 0; i < arr.length; i++) {
    windowSum += arr[i];
    if (i >= k) windowSum -= arr[i - k];  // Shrink from left
    if (i >= k - 1) maxSum = Math.max(maxSum, windowSum);  // Window is full
}

// Variable Size Window — Find minimum window satisfying condition
int left = 0, minLen = Integer.MAX_VALUE;
for (int right = 0; right < arr.length; right++) {
    // Expand: add arr[right] to window state
    
    while (windowSatisfiesCondition()) {
        minLen = Math.min(minLen, right - left + 1);
        // Shrink: remove arr[left] from window state
        left++;
    }
}

// Variable Size Window — Find maximum window satisfying condition
int left = 0, maxLen = 0;
for (int right = 0; right < arr.length; right++) {
    // Expand: add arr[right] to window state
    
    while (!windowSatisfiesCondition()) {
        // Shrink: remove arr[left] from window state
        left++;
    }
    maxLen = Math.max(maxLen, right - left + 1);
}

// Sliding Window with HashMap (character frequency)
Map<Character, Integer> window = new HashMap<>();
int left = 0;
for (int right = 0; right < s.length(); right++) {
    char c = s.charAt(right);
    window.merge(c, 1, Integer::sum);
    
    while (/* window invalid */) {
        char d = s.charAt(left);
        window.merge(d, -1, Integer::sum);
        if (window.get(d) == 0) window.remove(d);
        left++;
    }
    // update answer
}

Warm-Up Problems

Warm-up Sum Pair. Given a sorted array, find if any two elements sum to a target. Use two pointers from both ends.
Solution

Sort first (if not sorted). L=0, R=n−1: sum==t → found; sum<t → L++; else R−−. Each step discards one element: O(n).

Warm-up Remove Duplicates. Given a sorted array, remove duplicates in-place using fast/slow pointers.
Solution

slow=0; fast scans 1..n−1; when a[fast]≠a[slow]: slow++, a[slow]=a[fast]. Answer length slow+1. O(n)/O(1).

Warm-up Max Sum K. Given an array and window size k, find the maximum sum of any contiguous subarray of size k.
Solution

Sum first k, then slide: add a[i], subtract a[i−k], track max. O(n) — each element enters/leaves once.

Check yourself

Three questions. Predict, don't peek — then verify against the lesson.

1. a=[1,2,4,6,8], target 10. First step (L=0,R=4, sum 9<10)?

Explanation

Sum too small with the largest partner: a[L] is dead. L++.

2. Fast/slow in-place dedup: why does it stay O(1) space?

Explanation

Slow is the boundary of finished output; fast scans. No second array.

3. Fixed window k slides: cost per step?

Explanation

The overlap between consecutive windows is k−1 elements; only two change.
