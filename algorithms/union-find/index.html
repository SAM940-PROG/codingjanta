Intuition

Near-O(1) connectivity with path compression + union by rank. Components, cycles, Kruskal, offline queries.

Learn: Find with path compression, union by rank, connected components, weighted UF  ·  Practice: Warm-ups -> Medium -> Hard

How to recognize this pattern

Reach for it when:
  • Dynamic connectivity queries (are x,y linked?).
  • Cycle detection in an undirected stream.
  • Kruskal, components, offline deletions (reverse-time).
  • Grouping / equivalence classes.
Red flags — probably NOT this:
  • Directed reachability — DSU can't do direction.
  • Need the actual path, not just connectivity.
  • Splits/deletions online — DSU only merges.

Worked example — Redundant Connection

Problem. Edges [[1,2],[1,3],[2,3]]. Which edge closes a cycle?

  1. What should we notice? First edge whose endpoints already share a set is the answer.
  2. Naive thought. BFS per edge from scratch: O(n·E).
  3. Key observation. Union with path compression: find returns the representative; equal representatives ⇒ cycle.
  4. Optimized strategy. union(1,2); union(1,3) → {1,2,3}; edge (2,3): find= same → redundant.
  5. Step-by-step. Components twin: count distinct representatives after all unions.
  6. Final answer. [2,3].
  7. Complexity. ~O(E α(n)) — effectively linear.
  8. What to remember. Find with compression, union by rank. 1-indexed input → size n+1 arrays.

Topic 17 · Union-Find (Disjoint Set Union)

When would you actually use this? Use Union-Find when you need to efficiently check connectivity or merge groups -- cycle detection, connected components, Kruskal's MST, and grouping problems.

Algorithm — Optimized Union-Find

class UnionFind {
    int[] parent, rank;
    int components;
    
    UnionFind(int n) {
        parent = new int[n];
        rank = new int[n];
        components = n;
        for (int i = 0; i < n; i++) parent[i] = i;
    }
    
    // Find with Path Compression — nearly O(1) amortized
    int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }
    
    // Union by Rank
    boolean union(int x, int y) {
        int px = find(x), py = find(y);
        if (px == py) return false;  // Already connected
        if (rank[px] < rank[py]) { int t = px; px = py; py = t; }
        parent[py] = px;
        if (rank[px] == rank[py]) rank[px]++;
        components--;
        return true;
    }
    
    boolean connected(int x, int y) { return find(x) == find(y); }
    int getComponents() { return components; }
}

// Weighted Union-Find (track component sizes)
class WeightedUF {
    int[] parent, size;
    
    WeightedUF(int n) {
        parent = new int[n];
        size = new int[n];
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }
    }
    
    int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }
    
    void union(int x, int y) {
        int px = find(x), py = find(y);
        if (px == py) return;
        if (size[px] < size[py]) { int t = px; px = py; py = t; }
        parent[py] = px;
        size[px] += size[py];
    }
    
    int getSize(int x) { return size[find(x)]; }
}

Why?

Union-Find supports near-O(1) union and find operations. Essential for Kruskal's MST, dynamic connectivity, detecting cycles in undirected graphs, and grouping problems.

Check yourself

Three questions. Predict, don't peek — then verify against the lesson.

1. Without path compression, worst case is?

Explanation

Repeated unions can line up; compression + rank keep trees flat.

2. union(a,b) when find equal means?

Explanation

A second path between them just closed: that's a cycle.

3. Inverse Ackermann α(n) means?

Explanation

Amortized near-O(1): the famous 'almost constant'.
