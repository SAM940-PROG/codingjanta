Topic 16 · Minimum Spanning Tree (Kruskal & Prim)

LevelC
PrerequisitesGraphs, Union-Find, sorting
Estimated time60 min
ProgressionWarm-up → Easy → Medium → Hard
Learn → Understand → Dry run → Warm-up → Easy → Medium → Hard → Review

Intuition

Cheapest way to connect everything: sort edges (Kruskal) or grow the tree (Prim). Cut property justifies both.

Learn: Kruskal (edge-based), Prim (vertex-based), Union-Find for cycle detection  ·  Practice: Warm-ups -> Medium -> Hard

How to recognize this pattern

Reach for it when:
  • 'Connect all nodes with minimum total cost'.
  • Network design, clustering, spanning language.
  • Edge-sorted greedily works (cut property).
Red flags — probably NOT this:
  • Need shortest paths between specific nodes — that's shortest-path, not MST.
  • Directed edges — MST needs undirected (think arborescence instead).
  • Maximum bottleneck path — MST helps, but sort + DSU answers directly.

Worked example — Kruskal on 4 nodes

Problem. Edges: 1-2:1, 2-3:2, 1-3:3, 3-4:4, 2-4:5. Minimum total?

  1. What should we notice? Sort edges; take unless it closes a cycle (DSU).
  2. Naive thought. Enumerate all spanning trees: exponential.
  3. Key observation. Cut property: the cheapest edge crossing any cut belongs to some MST — Kruskal's greedy is provably safe.
  4. Optimized strategy. Sorted: take 1-2 (1); take 2-3 (2); skip 1-3 (cycle); take 3-4 (4) → 3 edges, done.
  5. Step-by-step. Prim twin: grow one tree, always attach the cheapest frontier edge — same total, better for dense graphs.
  6. Final answer. 1+2+4 = 7.
  7. Complexity. O(E log E) sort + ~O(E α(V)) unions.
  8. What to remember. Sort, union unless same set. Total weight in long.

Algorithm — Kruskal's (Edge-based, uses Union-Find)

// O(E log E) — Sort edges, greedily add if no cycle
int kruskal(int n, int[][] edges) {
    Arrays.sort(edges, (a, b) -> a[2] - b[2]);  // Sort by weight
    int[] parent = new int[n], rank = new int[n];
    for (int i = 0; i < n; i++) parent[i] = i;
    
    int mstWeight = 0, edgesUsed = 0;
    for (int[] edge : edges) {
        int u = edge[0], v = edge[1], w = edge[2];
        if (find(parent, u) != find(parent, v)) {
            union(parent, rank, u, v);
            mstWeight += w;
            if (++edgesUsed == n - 1) break;
        }
    }
    return mstWeight;
}

Algorithm — Prim's (Vertex-based, uses PriorityQueue)

// O((V + E) log V) — Grow MST from a vertex
int prim(int n, List<List<int[]>> adj) {
    boolean[] inMST = new boolean[n];
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[1] - b[1]); // {node, weight}
    pq.offer(new int[]{0, 0});
    int mstWeight = 0;
    
    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int u = curr[0], w = curr[1];
        if (inMST[u]) continue;
        inMST[u] = true;
        mstWeight += w;
        
        for (int[] edge : adj.get(u)) {
            if (!inMST[edge[0]]) pq.offer(new int[]{edge[0], edge[1]});
        }
    }
    return mstWeight;
}

Three questions. Predict, don't peek — then verify against the lesson.

1. Kruskal skips an edge when?

Explanation

Same DSU set = a path already exists; adding it only creates a cycle.

2. The greedy is safe because of?

Explanation

Every decision is the cheapest way across the grown-tree cut.

3. Prim vs Kruskal: prefer Prim when?

Explanation

Prim's heap processes the frontier; Kruskal's sort dominates on dense input.
