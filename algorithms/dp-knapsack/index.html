Topic 20 · Dynamic Programming — Knapsack Variants

Intuition

Choose items under capacity: 0/1 (once) vs unbounded (reuse) — loop order decides which. Subset-sum is the core reduction.

Learn: 0/1 knapsack, unbounded knapsack, subset sum, counting ways  ·  Practice: Warm-ups -> Medium -> Hard

How to recognize this pattern

Reach for it when:
  • Choose items under a capacity/weight limit.
  • Subset-sum / partition / target-sum phrasing.
  • 'Each item once' (0/1) vs 'unlimited reuse' (unbounded).
  • Counting ways vs max value under a budget.
Red flags — probably NOT this:
  • Items have no weight constraint — greedy/sort may do.
  • Fractional items allowed — greedy by ratio wins.

Worked example — Partition Equal Subset

Problem. Array [1,5,11,5]. Split into equal sums?

  1. What should we notice? Total 22 → need subset summing to 11: subset-sum DP.
  2. Naive thought. All 2ⁿ subsets: fine for n≤20, dead beyond.
  3. Key observation. Boolean dp[s]: reachable sums. For each item, sweep s downward (0/1: no reuse).
  4. Optimized strategy. dp after items: {0} → {0,1} → {0,1,5,6} → {0,1,5,6,11,12,16,17} → 11 reachable ✓ (11 alone).
  5. Step-by-step. Unbounded twin: same loop upward — coin change ways.
  6. Final answer. True.
  7. Complexity. O(n·sum) time, O(sum) space. Check total parity first.
  8. What to remember. Capacity-outer/item-inner direction decides once vs reuse.

Interactive dry run — 0/1 knapsack

Capacity is scanned downward so each item is used at most once.

Quick reference

Topic 20 · Dynamic Programming — Knapsack Variants

When would you actually use this? Use knapsack DP when you need to select items with constraints (weight, capacity) to maximize value. 0/1 knapsack for each item once, unbounded for unlimited reuse.

Algorithms

// ── 0/1 Knapsack ──
// dp[i][w] = max value using first i items with capacity w
int knapsack01(int[] weights, int[] values, int W) {
    int n = weights.length;
    int[] dp = new int[W + 1];  // Space-optimized to 1D
    for (int i = 0; i < n; i++)
        for (int w = W; w >= weights[i]; w--)  // Reverse for 0/1
            dp[w] = Math.max(dp[w], dp[w - weights[i]] + values[i]);
    return dp[W];
}

// ── Unbounded Knapsack (items can be reused) ──
int knapsackUnbounded(int[] weights, int[] values, int W) {
    int[] dp = new int[W + 1];
    for (int w = 1; w <= W; w++)
        for (int i = 0; i < weights.length; i++)
            if (weights[i] <= w)
                dp[w] = Math.max(dp[w], dp[w - weights[i]] + values[i]);
    return dp[W];
}

// ── Subset Sum (Boolean Knapsack) ──
boolean canPartition(int[] nums, int target) {
    boolean[] dp = new boolean[target + 1];
    dp[0] = true;
    for (int num : nums)
        for (int j = target; j >= num; j--)
            dp[j] = dp[j] || dp[j - num];
    return dp[target];
}

// ── Count of Subsets with Given Sum ──
int countSubsets(int[] nums, int target) {
    int[] dp = new int[target + 1];
    dp[0] = 1;
    for (int num : nums)
        for (int j = target; j >= num; j--)
            dp[j] += dp[j - num];
    return dp[target];
}

// ── Coin Change (Ways) — Unbounded Knapsack ──
int coinChangeWays(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    dp[0] = 1;
    for (int coin : coins)            // Outer loop = coin (prevents duplicate combos)
        for (int j = coin; j <= amount; j++)
            dp[j] += dp[j - coin];
    return dp[amount];
}

Warm-Up Problems

Warm-up Can Partition. Given an array, determine if it can be partitioned into two subsets with equal sum.
Warm-up Coin Ways. Given coins and an amount, find the number of ways to make the amount (unbounded).
Warm-up Target Sum. Given numbers and a target, find the number of ways to assign + or - to reach the target.

Explanation

Explanation

3. Unbounded coin-change-ways order?

Explanation

Check yourself

Three questions. Predict before you peek, then verify against the lesson.

1. 0/1 knapsack differs from unbounded because...

Explanation

0/1 uses each item once; unbounded allows reuse.

2. For 0/1 knapsack on a one-dimensional dp, capacity must be scanned...

Explanation

Downward prevents reading a state that already used the current item.

3. Subset-sum is a special case of knapsack where...

Explanation

Asking whether a target sum is reachable treats each value as both weight and value.
