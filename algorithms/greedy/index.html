Intuition

Locally optimal ⇒ globally optimal, with proof (exchange argument). Sorting by end-time/priority usually sets it up; when unsure, suspect DP.

Learn: Activity selection, interval scheduling, jump game, Huffman coding, greedy vs DP  ·  Practice: Warm-ups -> Easy -> Medium -> Hard

How to recognize this pattern

Reach for it when:
  • Activity/interval scheduling, minimum refuels, classic covering.
  • A natural 'best first' order (earliest end, largest, cheapest).
  • Exchange argument looks provable.
  • Local choice never harms the future.
Red flags — probably NOT this:
  • Choice now can trap you later (knapsack 0/1!) — suspect DP.
  • Need proof and can't sketch one — test vs brute on small cases first.

Worked example — Activity Selection

Problem. Intervals [(1,3),(2,4),(3,5),(0,6),(5,7)]. Max non-overlapping set?

  1. What should we notice? Earliest-finishing leaves maximum room: sort by end, take if compatible.
  2. Naive thought. All subsets: O(2ⁿ).
  3. Key observation. Exchange argument: some optimum contains the earliest-finishing activity, so taking it is always safe; repeat.
  4. Optimized strategy. Sorted by end: (1,3) take; (2,4) clash; (3,5) take; (0,6) clash; (5,7) take → 3.
  5. Step-by-step. Jump Game twin: track farthest reachable; greedily extend.
  6. Final answer. 3 activities.
  7. Complexity. O(n log n) sort + O(n) scan.
  8. What to remember. Sort by end, take compatible. No proof sketch → don't trust it.

Interactive dry run — Activity selection

Sort by end time, then take every activity that starts after the last chosen end.

Quick reference

Topic 22 · Greedy Algorithms

When would you actually use this? Use greedy when locally optimal choices lead to a globally optimal solution. Activity selection, interval scheduling, and Huffman coding are classic examples.

Why?

Greedy algorithms make the locally optimal choice at each step, hoping it leads to a globally optimal solution. They work when the problem has "greedy choice property" and "optimal substructure". They're typically simpler and faster than DP when applicable.

Classic Algorithms

// ── Activity Selection / Interval Scheduling ──
// Maximize number of non-overlapping intervals
int maxActivities(int[][] intervals) {
    Arrays.sort(intervals, (a, b) -> a[1] - b[1]);  // Sort by end time!
    int count = 1, lastEnd = intervals[0][1];
    for (int i = 1; i < intervals.length; i++) {
        if (intervals[i][0] >= lastEnd) {
            count++;
            lastEnd = intervals[i][1];
        }
    }
    return count;
}

// ── Jump Game ──
boolean canJump(int[] nums) {
    int maxReach = 0;
    for (int i = 0; i < nums.length; i++) {
        if (i > maxReach) return false;
        maxReach = Math.max(maxReach, i + nums[i]);
    }
    return true;
}

// ── Huffman Coding (using PriorityQueue) ──
int huffman(int[] freq) {
    PriorityQueue<Integer> pq = new PriorityQueue<>();
    for (int f : freq) pq.offer(f);
    int cost = 0;
    while (pq.size() > 1) {
        int a = pq.poll(), b = pq.poll();
        cost += a + b;
        pq.offer(a + b);
    }
    return cost;
}
