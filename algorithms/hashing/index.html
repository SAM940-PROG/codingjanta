Topic 10 · Hashing Patterns

LevelC
PrerequisitesArrays, basic data structures
Estimated time60–90 min
ProgressionWarm-up → Easy → Medium → Hard
Learn → Understand → Dry run → Warm-up → Easy → Medium → Hard → Review

Intuition

Trade memory for speed: frequencies, membership, and prefix+map turn O(n²) pair hunts into O(n). Most versatile contest pattern.

Learn: Frequency counting, two-sum pattern, grouping, prefix sum + hash map  ·  Practice: Warm-ups -> Easy -> Medium -> Hard

How to recognize this pattern

Reach for it when:
  • 'Find/count/group/duplicate' phrasing.
  • Pair problems (two-sum, complements, prefix-difference).
  • Frequency or first-occurrence questions.
  • An O(n²) brute force whose inner lookup could be O(1).
Red flags — probably NOT this:
  • Order matters (min/max/range) — consider sorting/trees.
  • Keys need hashing you can't define (use indices/sorting).
  • Memory is extremely tight and data is sortable — sort + two pointers may win.

Worked example — Two Sum — one pass

Problem. Array [2,7,11,15], target 9. Return indices.

  1. What should we notice? For each x, the partner is forced: need=9−x. A map of seen values answers 'have I seen need?' in O(1).
  2. Naive thought. All pairs: O(n²).
  3. Key observation. Complement lookup converts search into memory: store each value as you go, so pairs are found the moment they complete.
  4. Optimized strategy. x=2: need 7, unseen → store {2:0}. x=7: need 2 — seen at 0 ✓.
  5. Step-by-step. Same skeleton counts subarrays with sum K (store prefix frequencies) and groups anagrams (store sorted-key buckets).
  6. Final answer. Indices (0,1).
  7. Complexity. O(n) time, O(n) space.
  8. What to remember. Pair/complement/frequency → hashmap. Ask 'what would I need to have seen?'

Core Patterns

// Pattern 1: Frequency Counting
Map<Integer, Integer> freq = new HashMap<>();
for (int num : arr) freq.merge(num, 1, Integer::sum);

// Pattern 2: Two Sum (Complement Lookup)
Map<Integer, Integer> seen = new HashMap<>(); // value -> index
for (int i = 0; i < nums.length; i++) {
    if (seen.containsKey(target - nums[i])) return new int[]{seen.get(target - nums[i]), i};
    seen.put(nums[i], i);
}

// Pattern 3: Subarray Sum Equals K (Prefix Sum + HashMap)
Map<Integer, Integer> prefixCount = new HashMap<>();
prefixCount.put(0, 1);
int sum = 0, count = 0;
for (int num : nums) {
    sum += num;
    count += prefixCount.getOrDefault(sum - k, 0);
    prefixCount.merge(sum, 1, Integer::sum);
}

// Pattern 4: Anagram Grouping
Map<String, List<String>> groups = new HashMap<>();
for (String s : strs) {
    char[] ca = s.toCharArray();
    Arrays.sort(ca);
    groups.computeIfAbsent(String.valueOf(ca), k -> new ArrayList<>()).add(s);
}

// Pattern 5: String Hashing (Rolling Hash — Rabin-Karp foundation)
long hash = 0, base = 31, mod = 1_000_000_007;
for (char c : s.toCharArray()) {
    hash = (hash * base + (c - 'a' + 1)) % mod;
}
💡 When would you actually use this? Use hashing when you need to count frequencies, check membership in O(1), group similar items, or detect duplicates. It's the most versatile pattern in competitive programming — it can turn an O(n²) brute force into an O(n) solution. Two Sum, anagram grouping, and sliding window frequency counting all rely on this pattern.

Check yourself

Three questions. Predict, don't peek — then verify against the lesson.

1. One-pass two-sum works because?

Explanation

Future elements can't complete a pair yet; past ones are all in the map.

2. Worst case for hashmap ops?

Explanation

Average O(1), worst O(n). Fine in practice, worth knowing in contests.

3. Group anagrams: the map key should be?

Explanation

Anagrams share a canonical form — that collision is exactly what you want.

Check yourself

Three questions. Predict before you peek, then verify against the lesson.

1. Average lookup time of a hash map is...

Explanation

With a good hash and load factor, buckets stay short.

2. Worst-case hash map lookup degrades to...

Explanation

Adversarial collisions chain everything into one bucket.

3. Prefix-sum + HashMap turns 'subarray sum equals k' into...

Explanation

Store running-sum frequencies and look up sum - k as you go.
