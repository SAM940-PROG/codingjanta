Topic 2 · Recursion & Backtracking

LevelF
PrerequisitesLoops, basic functions, problem decomposition

ProgressionWarm-up → Easy → Medium → Hard

Intuition

Solve smaller copies of the same problem: base case stops, recursive case shrinks. Backtracking is recursion + undo, enumerating all candidates.

Learn: Base case, recursive case, call stack  ·  Practice: Warm-ups -> Subsets -> Backtracking

How to recognize this

Reach for it when: Self-similar structure (trees, subsets, permutations); Exhaustive search with undo (backtracking); Divide & conquer halves.

Red flags: Deep linear chains (10⁵) — iterate; Overlapping subproblems without memo — that's DP missing its table.

Worked example — Subsets of [1,2]

Problem. Enumerate all subsets.

  1. What should we notice? Each element: take or skip — a binary decision tree of depth n.
  2. Naive thought. Bitmask loops work but hide the structure backtracking teaches.
  3. Key observation. Decide index i, recurse both branches, undo (pop) after the take-branch.
  4. Optimized strategy. {} → take 1 → {1} → take 2 → {1,2}; backtrack; skip 2 → {1}; backtrack; skip 1 → {} → take 2 → {2}.
  5. Step-by-step. Permutation twin: swap-into-position i, recurse, swap back.
  6. Final answer. {}, {1}, {2}, {1,2}.
  7. Complexity. O(n·2ⁿ) time (output-sized), O(n) stack.
  8. What to remember. Choose, recurse, undo. The undo is the difference between DFS and backtracking.

Interactive dry run — The call stack

Frames pile up going down, unwind coming back — depth is the risk.

Quick reference

Topic 2 · Recursion & Backtracking

When would you actually use this? Use recursion when a problem can be broken into smaller versions of itself -- like computing factorials, traversing trees, or generating all subsets/backtracking solutions.

Algorithm — Recursion Template

// Every recursive function has:
// 1. Base case(s) — when to stop
// 2. Recursive case(s) — break problem into smaller subproblems
// 3. Return value — combine subproblem results

public int solve(parameters) {
    // 1. Base case
    if (baseCaseCondition) return baseResult;
    
    // 2. Recursive calls
    int subResult = solve(smallerProblem);
    
    // 3. Combine and return
    return combine(subResult);
}

Algorithm — Backtracking Template

// Backtracking = Recursion + Pruning + Undo
// Used when exploring ALL possible solutions (or finding one valid solution)

List<List<Integer>> result = new ArrayList<>();

public void backtrack(List<Integer> current, int start, int[] candidates) {
    // 1. Check if current state is a valid solution
    if (isGoal(current)) {
        result.add(new ArrayList<>(current));  // MUST copy!
        return;
    }
    
    // 2. Try all choices
    for (int i = start; i < candidates.length; i++) {
        // Pruning: skip invalid choices early
        if (!isValid(candidates[i])) continue;
        
        // 3. Make choice
        current.add(candidates[i]);
        
        // 4. Recurse
        backtrack(current, i + 1, candidates);  // i+1 for combinations, i for reuse
        
        // 5. Undo choice (backtrack)
        current.remove(current.size() - 1);
    }
}

Why?

Recursion decomposes complex problems into smaller, self-similar subproblems. Backtracking extends this by exploring a decision tree and pruning invalid branches early, making exhaustive search feasible.

Example — Generate All Subsets

public List<List<Integer>> subsets(int[] nums) {
    List<List<Integer>> result = new ArrayList<>();
    backtrack(result, new ArrayList<>(), nums, 0);
    return result;
}

private void backtrack(List<List<Integer>> result, List<Integer> current, int[] nums, int start) {
    result.add(new ArrayList<>(current));  // Every state is a valid subset
    for (int i = start; i < nums.length; i++) {
        current.add(nums[i]);
        backtrack(result, current, nums, i + 1);
        current.remove(current.size() - 1);
    }
}

Check yourself

Three questions. Predict before you peek, then verify against the lesson.

1. Every correct recursion must have...

Explanation

Without a shrinking base case the calls never stop.

2. Backtracking = recursion + ...

Explanation

Apply a choice, recurse, then revert it so sibling branches see a clean state.

3. Deep recursion on a long input risks...

Explanation

Java's call stack is finite; convert to iteration when depth can be large.
