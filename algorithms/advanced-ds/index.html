Intuition

Static RMQ (sparse table), LCA by binary lifting, HLD for tree paths. Specialized but decisive in their niche.

Learn: Sparse table, LCA (binary lifting), HLD, RMQ  ·  Practice: Warm-ups -> Hard

How to recognize this

Reach for it when: Static RMQ flood (sparse table); Tree path queries (LCA/HLD); K-th ancestor / binary lifting shapes.

Red flags: Dynamic updates — segment tree instead; Small n — naive O(n) per query is fine.

Worked example — Range minimum with a sparse table

Problem. Array [7, 2, 3, 0, 5, 10, 3, 12]. Answer many static min queries, e.g. min on [1, 6].

  1. What should we notice? No updates are requested, and there are many queries. That is the sparse-table signal.
  2. Naive thought. Scan each range: O(n) per query, O(n·q) total — too slow when q is large.
  3. Key observation. min is idempotent: min(x, x) = x. So a query can be covered by two overlapping power-of-two blocks and combined in O(1).
  4. Precompute. table[k][i] = min over a block of length 2^k starting at i. Built in O(n log n) by combining two 2^(k-1) blocks.
  5. Query [1, 6]. Length 6, k = 2 (block 4): min(table[2][1], table[2][3]) = min(min(2,3,0,5), min(0,5,10,3)) = min(0, 0) = 0.
  6. Final answer. 0.
  7. Complexity. O(n log n) build, O(1) per query, O(n log n) memory.
  8. What to remember. Overlap is fine only for idempotent operations. Sums need disjoint blocks (prefix sums or segment tree).

Algorithm — Sparse Table (Static RMQ)

// O(n log n) build, O(1) query for min/max (idempotent operations)
// NO updates supported!
class SparseTable {
    int[][] table;
    int[] log;
    int n;
    
    SparseTable(int[] arr) {
        n = arr.length;
        int K = (int)(Math.log(n) / Math.log(2)) + 1;
        table = new int[K][n];
        log = new int[n + 1];
        
        for (int i = 2; i <= n; i++) log[i] = log[i / 2] + 1;
        
        // Base case
        for (int i = 0; i < n; i++) table[0][i] = arr[i];
        
        // Build
        for (int k = 1; k < K; k++)
            for (int i = 0; i + (1 << k) <= n; i++)
                table[k][i] = Math.min(table[k-1][i], table[k-1][i + (1 << (k-1))]);
    }
    
    // Query min in [l, r]
    int query(int l, int r) {
        int k = log[r - l + 1];
        return Math.min(table[k][l], table[k][r - (1 << k) + 1]);
    }
}

Algorithm — LCA (Binary Lifting)

// O(n log n) preprocessing, O(log n) per query
int LOG = 20;
int[][] up = new int[LOG][n];  // up[k][v] = 2^k-th ancestor of v
int[] depth = new int[n];

void dfs(int v, int parent, int d) {
    up[0][v] = parent;
    depth[v] = d;
    for (int k = 1; k < LOG; k++)
        up[k][v] = up[k-1][up[k-1][v]];
    for (int u : adj.get(v))
        if (u != parent) dfs(u, v, d + 1);
}

int lca(int u, int v) {
    if (depth[u] < depth[v]) { int t = u; u = v; v = t; }
    int diff = depth[u] - depth[v];
    for (int k = 0; k < LOG; k++)
        if (((diff >> k) & 1) == 1) u = up[k][u];
    if (u == v) return u;
    for (int k = LOG - 1; k >= 0; k--)
        if (up[k][u] != up[k][v]) { u = up[k][u]; v = up[k][v]; }
    return up[0][u];
}

Heavy-Light Decomposition (HLD)

// Decomposes a tree into chains for path queries using Segment Tree
// O(n) preprocessing, O(log²n) per query/update
// Key idea: any path from root to leaf crosses at most O(log n) chains

// Steps:
// 1. DFS to compute subtree sizes, parents, depths
