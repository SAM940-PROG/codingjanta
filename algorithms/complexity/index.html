Topic 1 · Time & Space Complexity (Big-O)

LevelF
PrerequisitesNone
Estimated time60–90 min
ProgressionWarm-up → Easy → Medium → Hard
Learn → Understand → Dry run → Warm-up → Easy → Medium → Hard → Review

Intuition

Big-O describes growth, not speed: it tells you before coding whether brute force survives the constraints. Learn to read O(1)/O(n)/O(n²)/O(log n) off code shape.

Common mistakes

  • Adding complexities of sequential loops (take max, don't multiply).
  • Forgetting the hidden log factor from sort inside a loop.

Worked example — Estimation drill

Problem. n=2·10⁵, 1 s limit. Which survives: O(n²), O(n log n), O(n√n)?

  1. What should we notice? Convert growth to operations: n²=4·10¹⁰ ✗; n log n≈3.6·10⁶ ✓; n√n≈9·10⁷ borderline-but-ok in Java.
  2. Naive thought. Code first, time out later: the most expensive contest habit.
  3. Key observation. 1 s ≈ 10⁸ simple ops. Multiply by query counts: q=10⁵ × O(n) scan = 10¹⁰ ✗ → prefix/O(1) or log structure.
  4. Optimized strategy. Sorting 2·10⁵ ints: ~3.6M comparisons ✓. Nested loop over it: 4·10¹⁰ ✗ — need the pattern upgrade.
  5. Step-by-step. Query twin: 10⁵ range sums → O(n·q) dead, prefix O(n+q) alive.
  6. Final answer. O(n log n) and better.
  7. Complexity. Estimation itself is O(1) and saves hours.
  8. What to remember. Read constraints first; pick the complexity class before the algorithm.

Interactive dry run — Growth vs. constraints

Same n, five growth rates: see which survive a one-second limit before you write any code.

Master Theorem (Recurrences)

// For T(n) = aT(n/b) + O(n^d):
// Case 1: d < log_b(a) → T(n) = O(n^(log_b(a)))
// Case 2: d = log_b(a) → T(n) = O(n^d × log n)
// Case 3: d > log_b(a) → T(n) = O(n^d)

// Examples:
// Binary Search:    T(n) = T(n/2) + O(1)      → O(log n)
// Merge Sort:       T(n) = 2T(n/2) + O(n)     → O(n log n)
// Strassen's:       T(n) = 7T(n/2) + O(n²)    → O(n^2.81)

Amortized Analysis

Some operations are expensive occasionally but cheap on average: ArrayList.add() is O(1) amortized even though it's O(n) when resizing. Union-Find with path compression + rank is O(α(n)) ≈ O(1) amortized.

Check yourself

Three questions. Predict, don't peek — then verify against the lesson.

1. 1 s, n=10⁵: O(n²) is?

Explanation

10⁵² = 10¹⁰ ≈ 100 s. You need O(n log n) or better.

2. Sort inside a loop over n costs?

Explanation

n iterations × n log n sort. Precompute or restructure.

3. Space-time tradeoff example?

Explanation

Memory for speed is the standard contest bargain.

Check yourself

Three questions. Predict before you peek, then verify against the lesson.

1. Two sequential loops of size n cost...

Explanation

Sequential work adds: n + n = O(n). Nested loops multiply.

2. n = 10^5 with a 1-second limit suggests a target of at most...

Explanation

n log n is about 1.7e6 operations; n^2 would be 1e10.

3. A sort hidden inside a loop over n adds...

Explanation

Each iteration's O(n log n) sort compounds to O(n^2 log n) overall.
