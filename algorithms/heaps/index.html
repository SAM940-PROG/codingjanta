Intuition

Repeated min/max access in O(log n): top-k, scheduling, Dijkstra. Two heaps give running medians.

Learn: Min-heap, max-heap, heapify, top-k pattern, two-heaps median, merge k sorted  ·  Practice: Warm-ups -> Easy -> Medium -> Hard

How to recognize this pattern

Reach for it when:
  • Repeated min/max extraction (top-k, merge k lists).
  • Scheduling by priority or deadline.
  • Running median / streaming order statistics.
  • Graph algorithms needing frontier minima (Dijkstra, Prim).
Red flags — probably NOT this:
  • Need arbitrary key lookup/deletion — use a map/tree.
  • All data known upfront and sorted once — just sort.

Worked example — Kth largest in a stream of values

Problem. Array [3,2,1,5,6,4], k=2.

  1. What should we notice? Only k champions matter: keep a min-heap of size k; its top is the kth largest.
  2. Naive thought. Sort fully: O(n log n) — wasteful when k is small.
  3. Key observation. Push x; if heap exceeds k, evict the smallest. Survivors are exactly the k largest.
  4. Optimized strategy. push 3→[3]; 2→[2,3]; 1→ skip (1<2); 5→ evict→[3,5]; 6→ evict→[5,6]; 4→ skip. Top=5.
  5. Step-by-step. Median twin: two heaps (max-low, min-high) balanced within one.
  6. Final answer. 5.
  7. Complexity. O(n log k) time, O(k) space.
  8. What to remember. Min-heap of size k = kth-largest machine. Java PQ is min-first by default.

Interactive dry run — Insert + bubble up

New value enters at the end, then climbs while it beats its parent.

Quick reference

Topic 12 · Heaps / Priority Queues

When would you actually use this? Use heaps when you need to repeatedly access the minimum or maximum element. They are essential for greedy algorithms, scheduling, and graph algorithms like Dijkstra.

Algorithm — Heap Operations (Manual Implementation)

// Min-Heap using array (0-indexed)
// Parent: (i - 1) / 2
// Left child: 2 * i + 1
// Right child: 2 * i + 2

class MinHeap {
    int[] heap;
    int size;
    
    void siftUp(int i) {
        while (i > 0 && heap[(i - 1) / 2] > heap[i]) {
            swap(i, (i - 1) / 2);
            i = (i - 1) / 2;
        }
    }
    
    void siftDown(int i) {
        while (2 * i + 1 < size) {
            int smallest = 2 * i + 1;
            if (smallest + 1 < size && heap[smallest + 1] < heap[smallest])
                smallest++;
            if (heap[i] <= heap[smallest]) break;
            swap(i, smallest);
            i = smallest;
        }
    }
    
    void insert(int val) { heap[size++] = val; siftUp(size - 1); }
    int extractMin() { int min = heap[0]; heap[0] = heap[--size]; siftDown(0); return min; }
}

// Heapify entire array — O(n)
for (int i = n / 2 - 1; i >= 0; i--) siftDown(i);

Common Heap Patterns

// Pattern: Top K Elements
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
for (int num : nums) {
    minHeap.offer(num);
    if (minHeap.size() > k) minHeap.poll();
}
// minHeap now contains top k largest elements

// Pattern: Two Heaps (Median Finder)
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder()); // left half
PriorityQueue<Integer> minHeap = new PriorityQueue<>();                          // right half

void addNum(int num) {
    maxHeap.offer(num);
    minHeap.offer(maxHeap.poll());
    if (minHeap.size() > maxHeap.size()) maxHeap.offer(minHeap.poll());
}

double findMedian() {
    return maxHeap.size() > minHeap.size() ? maxHeap.peek()
        : (maxHeap.peek() + minHeap.peek()) / 2.0;
}

// Pattern: Merge K Sorted Lists
PriorityQueue<ListNode> pq = new PriorityQueue<>((a, b) -> a.val - b.val);
for (ListNode head : lists) if (head != null) pq.offer(head);
ListNode dummy = new ListNode(0), tail = dummy;
while (!pq.isEmpty()) {
    ListNode node = pq.poll();
    tail.next = node;
    tail = tail.next;
    if (node.next != null) pq.offer(node.next);
}

Check yourself

Three questions. Predict, don't peek — then verify against the lesson.

1. Min-heap of size k for kth largest: after processing, the top is?

Explanation

The heap holds the k largest; its minimum is the kth.

2. Decrease-key in Java's PQ is handled by?

Explanation

No efficient decrease-key: lazy deletion keeps it O(log n).

3. Heapify n elements costs?

Explanation

Bottom-up sift-downs: most nodes sit near leaves with tiny heights.
