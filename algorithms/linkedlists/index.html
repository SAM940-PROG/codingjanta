Intuition

Dummy head, reversal, fast/slow, merge: four moves solve most list problems. Draw pointers before coding.

Learn: Dummy head, fast/slow, reversal, merge two sorted lists, cycle detection  ·  Practice: Warm-ups -> Easy -> Medium -> Hard

How to recognize this pattern

Reach for it when:
  • Nodes/pointers/reversal/cycle language.
  • k-th from end, middle finding (fast/slow).
  • Merge two ordered sequences.
  • In-place reorder with O(1) space pressure.
Red flags — probably NOT this:
  • Indexed access dominates — use an array/list.
  • Frequent search by value — add a map or rethink.

Worked example — Reverse a list

Problem. Reverse 1→2→3 in one pass, O(1) space.

  1. What should we notice? Rewiring needs three actors: prev, curr, and saved next.
  2. Naive thought. Copy values to an array and rebuild: O(n) extra space.
  3. Key observation. Reverse each link as you walk: curr.next=prev, then advance both. Saving next first is the whole trick — otherwise the tail is lost.
  4. Optimized strategy. prev=null,curr=1: save 2; 1→null; advance. curr=2: save 3; 2→1; advance. curr=3: save null; 3→2; advance. curr=null → return prev (3).
  5. Step-by-step. Dummy-head twin: deletions/insertions at position 0 stop being special cases.
  6. Final answer. 3→2→1.
  7. Complexity. O(n) time, O(1) space.
  8. What to remember. Save next, flip, advance. Dummy head kills edge cases.

Interactive dry run — Pointer rewiring

Follow prev/curr/next — the link flips before anything advances.

Algorithm — Core Patterns

// ListNode definition
class ListNode {
    int val;
    ListNode next;
    ListNode(int val) { this.val = val; }
}

// Pattern 1: Dummy Head (simplifies edge cases)
ListNode dummy = new ListNode(0);
dummy.next = head;
// ... manipulate list ...
return dummy.next;

// Pattern 2: Two Pointers (Fast & Slow) — Cycle Detection (Floyd's)
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow == fast) return true;  // Cycle detected
}
return false;

// Pattern 3: Find Middle
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
}
// slow is now at the middle

// Pattern 4: Reverse a Linked List (Iterative)
ListNode prev = null, curr = head;
while (curr != null) {
    ListNode next = curr.next;
    curr.next = prev;
    prev = curr;
    curr = next;
}
return prev;  // New head

// Pattern 5: Merge Two Sorted Lists
ListNode dummy = new ListNode(0), tail = dummy;
while (l1 != null && l2 != null) {
    if (l1.val <= l2.val) { tail.next = l1; l1 = l1.next; }
    else { tail.next = l2; l2 = l2.next; }
    tail = tail.next;
}
tail.next = (l1 != null) ? l1 : l2;
return dummy.next;

Check yourself

Three questions. Predict, don't peek — then verify against the lesson.

1. Fast/slow finds the middle because?

Explanation

Distance ratio 2:1 invariant — no length precompute needed.

2. Forgetting to save next before rewiring causes?

Explanation

curr.next is your only handle on the tail — overwrite it blindly and it's gone.

3. Cycle detection (Floyd) terminates because?

Explanation

Relative speed 1 step/round guarantees a meeting in a cycle; null ends acyclic lists.
