Intuition

Shared-prefix tree: O(L) insert/query by word length. Autocomplete, prefix counts, XOR extremum.

Learn: Trie structure, insert/search/startsWith, count words with prefix, XOR trie  ·  Practice: Warm-ups -> Easy -> Medium -> Hard

How to recognize this

Reach for it when: Prefix queries / autocomplete / word-break dictionaries; XOR-maximum pair problems; Shared-prefix compression over many strings.

Red flags: Substring (not prefix) search — suffix automaton/KMP instead; Tiny dictionaries — a HashSet is simpler.

Worked example — Insert and prefix search

Problem. Insert ["apple", "app", "apt"], then answer: is "app" a word? Does any word start with "ap"?

  1. What should we notice? Shared-prefix queries over a set of strings are the trie signal.
  2. Naive thought. Scan all words: O(total characters) per query — wasteful when many queries share prefixes.
  3. Key observation. Walk character by character; common prefixes share one path, so a prefix question costs O(prefix length).
  4. Insert. "apple" creates a→p→p→l→e; "app" reuses a→p→p and marks its end; "apt" branches at the third character.
  5. Query "app". Walk a, p, p; the node exists and has an end-of-word flag → true.
  6. Query prefix "ap". Walk a, p; the node exists (children continue) → true.
  7. Complexity. O(L) per operation for key length L, independent of the number of stored words.
  8. What to remember. The end-of-word flag is what separates "prefix" from "word". XOR tries answer max-XOR queries the same way.

Interactive dry run — Trie prefix walk

The query walks one node per character; missing children prune an entire subtree.

Quick reference

Topic 13 · Tries (Prefix Trees)

When would you actually use this? Use tries when you need prefix-based queries -- autocomplete, spell checking, or XOR-based problems. They enable O(L) lookups where L is the word length.

Algorithm

class TrieNode {
    TrieNode[] children = new TrieNode[26];
    boolean isEndOfWord = false;
    int count = 0;  // Optional: count words with this prefix
}

class Trie {
    TrieNode root = new TrieNode();
    
    void insert(String word) {
        TrieNode node = root;
        for (char c : word.toCharArray()) {
            int idx = c - 'a';
            if (node.children[idx] == null) node.children[idx] = new TrieNode();
            node = node.children[idx];
            node.count++;
        }
        node.isEndOfWord = true;
    }
    
    boolean search(String word) {
        TrieNode node = findNode(word);
        return node != null && node.isEndOfWord;
    }
    
    boolean startsWith(String prefix) {
        return findNode(prefix) != null;
    }
    
    int countWordsWithPrefix(String prefix) {
        TrieNode node = findNode(prefix);
        return node == null ? 0 : node.count;
    }
    
    private TrieNode findNode(String s) {
        TrieNode node = root;
        for (char c : s.toCharArray()) {
            int idx = c - 'a';
            if (node.children[idx] == null) return null;
            node = node.children[idx];
        }
        return node;
    }
}

Why?

Tries enable O(L) lookup (L = word length) for prefix-based queries. Crucial for autocomplete, spell checking, word games, and XOR-based problems (bitwise trie).

Check yourself

Three questions. Predict before you peek, then verify against the lesson.

1. A trie lookup costs...

Explanation

Each character steps down one node; the cost depends only on the key length.

2. The end-of-word flag exists to distinguish...

Explanation

A prefix may exist as a path without being an inserted word.

3. A binary trie over bit representations is typically used for...

Explanation

Greedily choose the opposite bit at each level to maximize XOR.
