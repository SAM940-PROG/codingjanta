Topic 8 · Stacks & Monotonic Stacks

LevelC
PrerequisitesArrays, basic iteration
Estimated time60–90 min

Intuition

Stacks remember pending work; monotonic stacks additionally discard dominated candidates, turning O(n²) 'next greater' scans into O(n).

Learn: Stack basics, monotonic increasing/decreasing stacks, stock span, histogram  ·  Practice: Warm-ups -> Easy -> Medium -> Hard

How to recognize this pattern

Reach for it when:
  • Matching/nesting (brackets, tags, syntax).
  • 'Next greater/smaller element' or storm-survey shapes.
  • Undo history, call-like LIFO processing.
  • Monotonic candidates (histogram, stock span, daily temperatures).
Red flags — probably NOT this:
  • FIFO order needed — that's a queue.
  • Random access to the middle — use an array.

Worked example — Valid Parentheses

Problem. String “([])” — balanced?

  1. What should we notice? Openers are promises a closer must keep, in reverse order: LIFO.
  2. Naive thought. Repeatedly delete “()”/“[]”/“{}” pairs: O(n²) rescans.
  3. Key observation. Push openers; each closer must match the top. Mismatch, empty-pop, or leftover stack all mean unbalanced.
  4. Optimized strategy. ( push → [ ( ]; [ push → [(,[]; ] matches top ✓ pop; ) matches ✓ pop; end: empty → valid.
  5. Step-by-step. Monotonic twin: Daily Temperatures — keep a decreasing stack of indices; each hotter day resolves everyone it beats.
  6. Final answer. Valid.
  7. Complexity. O(n) time, O(n) space.
  8. What to remember. Stack = pending work. Monotonic stack = pending work minus dominated candidates.

Interactive dry run — Push / pop discipline

The top is the only thing you may touch — watch pending work resolve.

Algorithm — Monotonic Stack

// Next Greater Element (Monotonic Decreasing Stack)
// For each element, find the next element that is greater
public int[] nextGreaterElement(int[] arr) {
    int n = arr.length;
    int[] result = new int[n];
    Arrays.fill(result, -1);
    Deque<Integer> stack = new ArrayDeque<>();  // Stores indices
    
    for (int i = 0; i < n; i++) {
        while (!stack.isEmpty() && arr[stack.peek()] < arr[i]) {
            result[stack.pop()] = arr[i];
        }
        stack.push(i);
    }
    return result;
}

// Previous Smaller Element (Monotonic Increasing Stack)
public int[] prevSmallerElement(int[] arr) {
    int n = arr.length;
    int[] result = new int[n];
    Arrays.fill(result, -1);
    Deque<Integer> stack = new ArrayDeque<>();
    
    for (int i = 0; i < n; i++) {
        while (!stack.isEmpty() && arr[stack.peek()] >= arr[i]) {
            stack.pop();
        }
        if (!stack.isEmpty()) result[i] = arr[stack.peek()];
        stack.push(i);
    }
    return result;
}

// Largest Rectangle in Histogram — Classic Monotonic Stack
public int largestRectangleArea(int[] heights) {
    Deque<Integer> stack = new ArrayDeque<>();
    int maxArea = 0, n = heights.length;
    
    for (int i = 0; i <= n; i++) {
        int h = (i == n) ? 0 : heights[i];
        while (!stack.isEmpty() && heights[stack.peek()] > h) {
            int height = heights[stack.pop()];
            int width = stack.isEmpty() ? i : i - stack.peek() - 1;
            maxArea = Math.max(maxArea, height * width);
        }
        stack.push(i);
    }
    return maxArea;
}

Why?

Monotonic stacks solve "next/previous greater/smaller" problems in O(n). They're essential for histogram, stock span, temperature, and many optimization problems.

Check yourself

Three questions. Predict, don't peek — then verify against the lesson.

1. A closer mismatches the top — verdict?

Explanation

LIFO order is the contract; a mismatch can never be repaired later.

2. Monotonic decreasing stack for 'next greater' pops while?

Explanation

Current beats everything ≤ it to its left for all future queries.

3. Why ArrayDeque over legacy Stack?

Explanation

Same semantics, better performance, cleaner API.
