Intuition

Queues process in arrival order (BFS); deques with monotonicity track window max/min in O(n).

Learn: Queue basics, deque operations, monotonic deque, sliding window max/min  ·  Practice: Warm-ups -> Easy -> Medium -> Hard

How to recognize this pattern

Reach for it when:
  • Level-by-level processing (BFS, level order).
  • Sliding-window maximum/minimum (monotonic deque).
  • Task scheduling / FIFO simulation.
  • Buffering a stream in arrival order.
Red flags — probably NOT this:
  • LIFO needed — that's a stack.
  • Need max of ALL elements repeatedly — that's a heap.

Worked example — Level-order traversal

Problem. Tree [3,9,20,null,null,15,7] → levels.

  1. What should we notice? FIFO processes nodes in arrival order = level order.
  2. Naive thought. DFS + depth bookkeeping: works but fights the natural order.
  3. Key observation. Enqueue root; repeatedly dequeue, record, enqueue children. Queue length at each drain = one level.
  4. Optimized strategy. [3] → dequeue 3, enqueue 9,20 → dequeue 9,20, enqueue 15,7 → drain 15,7.
  5. Step-by-step. Graph twin: same loop with a visited set marked on enqueue.
  6. Final answer. [[3],[9,20],[15,7]].
  7. Complexity. O(n) time, O(width) space.
  8. What to remember. Queue = arrival order. For graphs, mark visited when enqueuing, not when dequeuing.

Topic 9 · Queues & Monotonic Queues

When would you actually use this? Use queues for FIFO processing (BFS) and monotonic deques for sliding window max/min problems. They maintain order while efficiently removing outdated elements.

Algorithm — Monotonic Deque (Sliding Window Max/Min)

// Sliding Window Maximum — O(n)
public int[] maxSlidingWindow(int[] nums, int k) {
    int n = nums.length;
    int[] result = new int[n - k + 1];
    Deque<Integer> deque = new ArrayDeque<>();  // Stores indices, decreasing values
    
    for (int i = 0; i < n; i++) {
        // Remove indices outside window
        while (!deque.isEmpty() && deque.peekFirst() < i - k + 1) {
            deque.pollFirst();
        }
        // Remove smaller elements (they'll never be the max)
        while (!deque.isEmpty() && nums[deque.peekLast()] < nums[i]) {
            deque.pollLast();
        }
        deque.offerLast(i);
        
        if (i >= k - 1) {
            result[i - k + 1] = nums[deque.peekFirst()];
        }
    }
    return result;
}

Check yourself

Three questions. Predict before you peek, then verify against the lesson.

1. BFS marks a node visited when it is...

Explanation

Marking on enqueue prevents the same node being queued many times (exponential re-visits otherwise).

2. A monotonic deque for sliding-window maximum keeps indices in...

Explanation

The front is always the current maximum; smaller values are discarded as dominated.

3. Java's PriorityQueue iteration order is...

Explanation

Only poll() follows heap order; iterating does not.
