Java contest setup

The small set of Java choices that decides verdicts: input that never TLEs, output that never flushes per line, collections used as intended, and the pitfalls behind the most common Wrong Answers.

Scope. API lookup lives in the Java reference section. This page is the contest subset: what to paste, what to avoid, and why.

Fast input + fast output

Scanner is too slow for 10^5+ tokens. Paste this once per contest:

import java.io.*;
import java.util.*;
public class Main {
  static class FS {
    private final InputStream in = System.in;
    private final byte[] buf = new byte[1 << 16];
    private int ptr = 0, len = 0;
    private int read() throws IOException {
      if (ptr >= len) { len = in.read(buf); ptr = 0; if (len <= 0) return -1; }
      return buf[ptr++];
    }
    int nextInt() throws IOException {
      int c, s = 1, v = 0;
      do { c = read(); } while (c <= ' ');
      if (c == '-') { s = -1; c = read(); }
      while (c > ' ') { v = v * 10 + c - '0'; c = read(); }
      return v * s;
    }
    long nextLong() throws IOException {
      int c; long s = 1, v = 0;
      do { c = read(); } while (c <= ' ');
      if (c == '-') { s = -1; c = read(); }
      while (c > ' ') { v = v * 10 + c - '0'; c = read(); }
      return v * s;
    }
  }
  public static void main(String[] a) throws Exception {
    FS fs = new FS();
    StringBuilder out = new StringBuilder();
    // out.append(ans).append('
'); ...
    System.out.print(out);
  }
}
Java CP Pitfall — output. Never System.out.println inside a 10^5-iteration loop. Accumulate in StringBuilder, print once. Complexity note: repeated string + in a loop is O(n^2).

Java CP Pitfall — comparators. Never (a, b) -> a - b: it overflows. Use Integer.compare(a, b), Long.compare, or Comparator.comparingInt. An inconsistent comparator corrupts TreeMap/TreeSet and can crash sort.

Performance pitfalls that cost verdicts

  • Boxing: Integer in a hot loop over 10^6 elements adds real constant factor and GC pressure. Prefer int[] for frequency/counting arrays.
  • Recursion depth: default stack handles roughly 10^4 frames. DFS on a 10^5-node chain overflows — write it iterative with an explicit ArrayDeque, or raise stack only where the judge allows (it usually does not).
  • Hash worst cases: adversarial keys degrade HashMap toward O(n). For counting with bounded values, a plain array always wins.
  • Mod arithmetic: % on negatives stays negative in Java — normalize with ((x % M) + M) % M; multiply with long before the mod.
  • Memory: adjacency as ArrayList<Integer>[] boxes every edge. At 2e5+ edges prefer int[] head/to/nxt (forward star) or accept the constant.

Graph + algorithm wiring

Adjacency build, BFS/DFS skeletons, Dijkstra with stale-skip, DSU with path compression, and Kahn's topo sort each live as copyable templates in their preset cards — search the Preset Catalog for “dijkstra”, “dsu”, or “topo”. Pattern choice comes first; this page only makes the Java fast.

Review

Before a contest: you can paste the scanner blind, you print via one StringBuilder, your comparators never subtract, and your DFS is iterative past 10^4 depth.
