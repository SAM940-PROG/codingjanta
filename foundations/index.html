Key notes

What Is an Algorithm?

An algorithm is simply a step-by-step procedure to solve a problem. Every recipe you've followed is an algorithm. Every GPS route is an algorithm.

What makes algorithms interesting is that the same problem can often be solved in many different ways — some fast, some slow, some elegant, some brute-force.

Big-O Without the Nonsense

Big-O answers: "How does the runtime grow as the input gets bigger?"

O(1) — Looking up one book on a shelf by its exact position. Input size doesn't matter.
O(n) — Scanning an entire shelf to find a book. Double the shelf, double the time.
O(n²) — Comparing every pair of people in a room. 10 people → ~50 comparisons. 1000 people → ~500,000 comparisons.
O(log n) — Binary search: repeatedly splitting a sorted search space in half. Finding a word in a dictionary by opening to the middle, then the half, then the quarter...

Arrays

An array stores elements in contiguous memory, indexed from 0. You can jump to any index instantly (O(1)). But inserting in the middle requires shifting everything after it (O(n)).

Think of it like a row of lockers — you can open any locker directly, but if you insert something in the middle, you have to move everything after it.

Link to existing section: Arrays & Strings

Maps (Key → Value)

A map stores pairs: a key maps to a value. Think: student ID → student, phone number → person, word → frequency.

HashMap gives O(1) average lookup. TreeMap keeps keys sorted for O(log n) access with ordering.

Link to existing section: HashMap

Sets (Uniqueness)

A set stores only unique elements. Use it for membership testing: "Have I seen this before?"

HashSet for O(1) average membership checks. TreeSet when you need sorted order.

Link to existing section: HashSet & TreeSet

Recursion

A function that calls itself to solve a smaller version of the same problem. Every recursive function needs:

Base case: When to stop (the smallest possible problem)
Recursive case: How to reduce the problem toward the base case

Think of it like Russian nesting dolls — each call opens one layer until you reach the smallest one.

How To Read Code in This Guide

  1. Identify inputs: What goes in? What types?
  2. Identify outputs: What comes out?
  3. Identify loops: How many times does it iterate?
  4. Identify data structures: What's being stored and how?
  5. Estimate complexity: How does runtime grow with input?
  6. Trace a small example: Walk through with n=3 or n=5

How To Approach a New Problem

1. Understand — Read the problem. What exactly is being asked?
2. Brute Force — What's the simplest correct solution?
3. Constraints — What are the limits on n? Time limit?
4. Pattern — Does this match a known pattern?
5. Optimize — Can hashing, sorting, two pointers, or DP help?
6. Implement — Write clean code with templates
7. Test — Edge cases: empty input, single element, duplicates, negative numbers
