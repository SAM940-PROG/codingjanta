6 · TreeMap<K, V>

LevelR
PrerequisitesHashMap, sorting
Estimated time20 min
ProgressionWarm-up → Easy → Medium → Hard

Intuition

Sorted key→value map in O(log n). Range views (headMap/tailMap) and floor/ceiling keys are its reason to exist.

Common mistakes

  • Null keys rejected (vs HashMap allows one).
  • Comparator inconsistent with equals causes 'missing' entries.

Quick reference

6 · TreeMap<K, V>

Red-Black tree-based sorted map. Use when you need ordered keys.

import java.util.TreeMap;

TreeMap<Integer, String> tm = new TreeMap<>();
tm.put(3, "c"); tm.put(1, "a"); tm.put(5, "e"); tm.put(2, "b");

// Navigation (all O(log n))
tm.firstKey();             // 1
tm.lastKey();              // 5
tm.firstEntry();           // 1=a
tm.lastEntry();            // 5=e
tm.lowerKey(3);            // 2 — strictly less
tm.higherKey(3);           // 5 — strictly greater
tm.floorKey(3);            // 3 — less or equal
tm.ceilingKey(3);          // 3 — greater or equal
tm.lowerEntry(3);          // 2=b
tm.higherEntry(3);         // 5=e
tm.pollFirstEntry();       // Remove and return smallest entry
tm.pollLastEntry();        // Remove and return largest entry

// Range Views
tm.headMap(3);             // Keys < 3
tm.tailMap(3);             // Keys >= 3
tm.subMap(2, 5);           // Keys in [2, 5)
tm.subMap(2, true, 5, true); // Keys in [2, 5]
tm.descendingMap();        // Reverse-order view
tm.navigableKeySet();      // NavigableSet view of keys

// All standard Map operations work too
tm.put(key, value);
tm.get(key);
tm.containsKey(key);
tm.remove(key);
tm.size();
tm.entrySet();
💡 TreeMap is indispensable for problems requiring sorted key access — e.g., interval scheduling, skyline problem, sliding window median.
