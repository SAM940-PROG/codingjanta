10 · Comparator & Comparable

LevelR
PrerequisitesSorting
Estimated time20 min
ProgressionWarm-up → Easy → Medium → Hard

Intuition

Defines ordering for sort() and TreeMap/TreeSet. Comparators must be consistent; never subtract (overflow) — use Integer.compare.

Common mistakes

  • a-b subtraction overflows — use Integer.compare / comparingInt.
  • Inconsistent comparator breaks TreeSet/TreeMap and sort (TimSort exception).

Quick reference

10 · Comparator & Comparable

import java.util.Comparator;

// ── Comparable (Natural ordering — implement in your class) ──
class Student implements Comparable<Student> {
    String name;
    int grade;
    
    @Override
    public int compareTo(Student other) {
        return this.grade - other.grade;  // Ascending by grade
    }
}

// ── Comparator (External / Custom ordering) ──

// Lambda style
list.sort((a, b) -> a.grade - b.grade);

// Method reference
list.sort(Comparator.comparingInt(s -> s.grade));

// Chained comparators
list.sort(Comparator.comparingInt((Student s) -> s.grade)
                     .thenComparing(s -> s.name));

// Reverse
list.sort(Comparator.comparingInt((Student s) -> s.grade).reversed());

// Null-safe
list.sort(Comparator.nullsFirst(Comparator.naturalOrder()));
list.sort(Comparator.nullsLast(Comparator.naturalOrder()));

// Sort 2D array by first element, then by second
Arrays.sort(intervals, (a, b) -> {
    if (a[0] != b[0]) return a[0] - b[0];
    return a[1] - b[1];
});

// ⚠ OVERFLOW WARNING: Don't use a - b for large integers!
// Use Integer.compare(a, b) instead
list.sort(Comparator.comparingInt(Integer::intValue));
Arrays.sort(arr, (a, b) -> Integer.compare(a[0], b[0]));
⚠ a - b can cause integer overflow! For safe comparison always prefer Integer.compare(a, b) or Long.compare(a, b).
